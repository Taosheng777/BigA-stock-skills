# 策略模板库（strategy-presets）

> 人类可读目录。**代码里 `scripts/screen.py` 的 `PRESETS` 为唯一事实来源**，改模板先改它，再同步本表。
> 每个模板 = 命名 + 问财问句 + 打分字段权重（字段名为 normalize 后标准名，方向 higher/lower）。

## 调用

```bash
python3 scripts/screen.py --preset <模板名> --top 15
```

## 四个种子模板

> **2026-07-15 起**：行情类打分列（最新涨跌幅/换手率/最新市盈率ttm/最新市净率）由脚本内置的**腾讯批量 enrichment 自动覆盖**（零问财额度），问句里不再需要这些展示词缀；只有问财专属列（主力资金流向/资金流入/归母净利同比/营收同比/净资产收益率）仍需出现在问句中。

### 放量突破
- **问句**：今日放量突破20日新高 近5日涨幅小于15% 近一年归母净利润同比增长 主力资金流向 净资产收益率 非ST 非创业板 非北交所
- **打分**：最新涨跌幅 .20↑ / 换手率 .15↑ / 主力资金流向 .25↑ / 归母净利润同比增长率 .15↑ / 净资产收益率 .15↑ / 最新市盈率ttm .05↓ / 最新市净率 .05↓
- 实测池子量级 ≈ 30–40。

### 低位反转
- **问句**：近一年涨跌幅小于-20% 股价站上5日均线 主力资金流向 非ST 非北交所
- **打分**：最新涨跌幅 .30↑ / 换手率 .20↑ / 主力资金流向 .30↑ / 最新市净率 .20↓
- 实测池子量级 ≈ 20–30。

### 业绩成长
- **问句**：近一年归母净利润同比增长大于30% 营业收入同比增长 净资产收益率大于10% 市盈率小于40 非ST 非北交所
- **打分**：归母净利润同比增长率 .30↑ / 营业收入同比增长率 .25↑ / 净资产收益率 .20↑ / 最新市盈率ttm .15↓ / 最新市净率 .10↓
- 实测池子量级 ≈ 15–20。

### 主力异动
- **问句**：主力资金连续3日净流入 今日放量 主力资金流向 资金流入 非ST 非北交所
- **打分**：主力资金流向 .40↑ / 资金流入 .20↑ / 换手率 .20↑ / 最新涨跌幅 .20↑
- 实测池子量级 ≈ 90–100。

## 自由口述（无模板）

```bash
python3 scripts/screen.py --query "<问财问句>" --top 15
```

- 把用户一句话改写为**标准问财问句**：保意图、术语标准化（如"放量"→"今日放量"、"超跌"→"近一年涨跌幅小于-X%"），尽量带 `非ST` 之类的基础排除。
- 用通用打分字段 `DEFAULT_FIELDS`：最新涨跌幅 .25↑ / 换手率 .15↑ / 主力资金流向 .25↑ / 归母净利润同比增长率 .15↑ / 净资产收益率 .20↑。
- **改写时把问财专属打分列词缀进问句尾部**（`主力资金流向 归母净利润同比增长 净资产收益率`）；行情列（换手率/涨跌幅/PE/PB）**不必写**，enrichment 自动覆盖。腾讯获取失败时脚本降级为问财返回列打分并在 JSON `enrich.note` 标记。

## 写问句的经验（避免 0 结果 / 打分落空）

- **⚠️ 问财专属打分列必须显式写进问句**：问财 `query2data` 只下发问句里出现过的指标列。主力资金流向/资金流入/归母净利同比/营收同比/净资产收益率若没写进问句，返回里就没这列 → 该列整列缺失、按缺列重归一。**追加指标词只增列、不改筛选结果集**（实测 36→36 不变），放心加。行情列（换手率/涨跌幅/市盈率/市净率）2026-07-15 起由腾讯 enrichment 确定性覆盖，与问句无关；腾讯对亏损股/ETF 的 PE/PB 哨兵值 0.00 已在脚本内转 None，不参与打分。
- **条件别堆太满**：每多一个强条件就指数级缩池。先跑一版核心条件，量太大再加限制。
- **避开模糊词**："机构关注度提升""强势"这类 问财 难量化的措辞会直接打到 0，删掉换成可量化条件。
- **池子太大**（>500）：加 1 个估值/质量闸门（如 `市盈率小于40`、`净资产收益率大于10%`）收窄。
- **池子为 0**：删掉最严的那个条件重试；脚本对空池子安全（返回空名单，不报错）。
- 调脚本前可先用 `python3 ~/.claude/skills/hithink-market-query/scripts/cli.py --query "<问句>" --limit 3` 探一下 `code_count`，量合适再正式跑。
