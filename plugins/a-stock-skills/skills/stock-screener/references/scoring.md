# 打分与缺口规则（scoring）

> 实现在 `scripts/screen.py`，本文解释口径。**打分只排数字，不产生任何文字判断。**（判断交 stock-buddy）

## MVP 打分流程

1. **取值清洗** `parse_value`：问财字段值 → float。
   - 裸数字串 `'12126646'`、科学计数法串 `'2.5356130847E8'` 均解析；
   - `万/亿` 换算，`%` 保留量级，千分位逗号去除；
   - 无法解析 / 空 / 布尔 → `None`（记为缺口）。
2. **字段名归一** `normalize_field_name`：剥 `@` 前缀、`[日期]` 后缀、`:子标记`。同名多变体取第一个非空值（`pick_value`）。
3. **截面百分位归一** `rank_percentile`：池内对每个字段按值排序取百分位 → `[0,1]`。
   - 并列取平均位次；`None` 不参与、保持 `None`；单值记 `0.5`（中性）。
   - `lower` 方向字段取 `1 - 百分位`。
4. **加权求和** `score`：`综合分 = Σ(百分位 × 权重) / Σ(已用权重) × 100`，缩放到 0–100。

## 缺口规则（复用 stock-buddy 铁律：不编数据）

- **某只缺某字段** → 该字段不计入它的分，剩余权重**重新归一**（`applied` 只累计实际用到的权重），并在分项 `parts` 里记 `None`。
- **某字段整池缺失** → 该列 `rank_percentile` 全 `None`，自然不进任何个股的分（等价于丢弃并重归一）。
- **某只所有字段全缺** → `综合分 = None`，HTML 里显示 `-`，排序时沉底。

## 为什么用 rank 百分位（而非 min-max）

- 抗极端值：一只票某字段离群不会把整列压扁。
- 跨字段可比：不同量纲（涨跌幅 % vs 主力净额 元）统一到 `[0,1]` 再加权。

## 透明性

- HTML 与 JSON 都输出每只的 `parts`（各字段归一后百分位），便于人工复核分数来源。
