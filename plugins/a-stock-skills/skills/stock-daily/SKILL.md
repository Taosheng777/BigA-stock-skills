# Stock Daily 盘后例行

按固定顺序完成投资 vault 的日终流转。只搬运、计算和核对已验证数据，不代写盘面观点，不生成交易建议。

本文件自包含，是 Claude Code 运行时适配器，git identity 使用 `[ai:claude]`。

## 配置段（装好后先改这里）

Vault 根路径必须改成你自己的 Obsidian 投资 vault（且该 vault 需已 `git init`，否则前后快照无法执行）。下列 vault 内相对路径是本 skill 假定的目录结构示例，可按自己的 vault 调整，但六步编排引用到的文件必须真实存在。

- Vault 根：`~/Documents/投资笔记`（示例占位，改成你的）
- 硬护栏：`00-系统/AI操作规则.md`
- 仓库规则：`00-系统/仓库架构与整理规则.md`
- 账户纪律：`01-投资体系/账户纪律计划书.md`
- 持仓：`03-持仓跟踪/持仓.md`
- 净值绩效：`02-每日复盘/账户净值与绩效.md`
- 台账：`09-选股池跟踪/选股策略胜率台账.md`
- 复盘目录：`02-每日复盘/每日复盘总结/`
- 次日目录：`08-下个交易日/`
- 首页：`投资笔记.md`
- 行情 CLI：`~/.claude/skills/hithink-market-query/scripts/cli.py`（需自装同花顺问财 CLI，见仓库 README 依赖说明）

## 硬边界

- 只在人在场时手动触发；不做定时、不创建 automation、cron 或后台监控。
- 不下单、不碰委托、不动钱，不替用户作买卖决定。
- 不编数据。每个行情数字必须带来源和数据日；缺失就写缺口。
- 不写未来行情。下一交易日的日期和待办可以写，但不得附带未来价格、涨跌幅或资金数据。
- 只写六处白名单：持仓、净值绩效、台账、当日复盘、次日清单、首页；不写 04/05/06/07，不更新 HTML 仪表盘。
- 白名单写入和 git 快照视为随本 skill 的启用一并授权，不逐次询问；范围外写入仍先问。
- 一个数据源或一个批次失败，只让对应步骤记 `未跑（原因）`；其他彼此独立的步骤可以继续。

## 运行前检查

1. `cd` 到 vault，读取硬护栏、仓库规则、账户纪律、持仓、台账、首页，以及当日已有复盘/交易记录和最新次日清单。先看真实文件，不沿用会话摘要。
2. 用系统时间确认当前日期和时区。默认例行数据日必须是“今天”；若用户明确指定补跑某个历史交易日，再使用指定日期。
3. `source ~/.zshrc`，只检查 `IWENCAI_API_KEY` 是否存在，绝不打印密钥。
4. 用 hithink 查询上证指数、沪深300、深证成指、创业板指、科创50的最新收盘价与涨跌幅，核对返回字段中的数据日。
5. 默认触发若拿不到“今天”的完整收盘数据，停止所有写入并回复 `未跑（今日非交易日、尚未收盘或当日收盘数据不可验证）`。不要把上一交易日数据冒充今天。

## 六步编排

### 1. git 快照（前）

在任何 vault 写入前执行：

```bash
git status --short
git add -A
git commit --allow-empty -m "[ai:claude] 盘后例行前快照 YYYY-MM-DD"
git rev-parse --short HEAD
```

记录前快照 hash。提交失败就停止所有写入；不要在没有回滚点时继续。

### 2. 刷新持仓与纪律对照

1. 从 `持仓.md` 读取股票账户现有代码、数量、成本和现金状态；若 `06-交易记录/` 有数据日当天的已验证成交记录，只读并据此同步数量和成本。没有成交来源时不得推测交易。
2. 按代码分批调用 hithink，查询数据日收盘价和涨跌幅。返回记录必须逐只核对代码、简称和日期；最多按 hithink 规则放宽重试 2 次。
3. 只有全部主动持仓都取得同一数据日的收盘价时，才更新股票账户表。任一标的缺失则整项写 `未跑（持仓行情不完整：代码列表）`，不做半套刷新。
4. 用明确公式计算：
   - 市值 = 持仓数量 × 收盘价。
   - 盈亏率 = `(收盘价 / 成本 - 1) × 100%`。
   - 仓位 = 总市值 / 总资产；只有现金或总资产有可追溯来源时才计算。
   - 单股集中度 = 单股市值 / 总资产；卫星总占比 = 卫星仓总市值 / 总资产。
5. 现金、总资产或成本没有券商/交易记录新证据时保留原值并显著标 `沿用估算，待券商核对`；不得把沿用值写成数据日实测值。基金账户无新来源时保持原样并说明未刷新。
6. 逐项读取账户纪律当前版本，不在 skill 内沿用旧阈值；一切阈值以纪律文件当前内容为准，本 skill 不内置任何数值。只写 `触发 / 未触发 / 无法核对`，不写买卖指令。
7. 更新 frontmatter、数据源说明、账户层面摘要、变更记录和待办；所有数字注明数据日。

### 2.5 更新净值与绩效

1. 读取 `账户净值与绩效.md` 的最近一行和数据日账户总资产；没有同日可靠总资产时写 `未跑（总资产无法验证）`，不估算净值。
2. 从当日交易记录识别外部资金流；买卖证券不是外部资金流。未知入金/出金不推测。
3. 按绩效页公式计算日收益、time-weighted return、净值、最大回撤和月内回撤。同一日期只允许一行，重复触发时更新原行。
4. 基准优先沪深300全收益指数；若稳定数据源只提供价格指数，首次锁定后固定使用价格指数，后续不得混用。
5. 最大回撤或月内回撤达到纪律文件设定阈值时，只把状态写为 `冻结新增风险仓` 并生成复核项；不自动卖出或生成委托。

### 3. 更新台账 T+N

1. 先读台账“记账规则”和所有批次汇总/明细，查重数据日。跳过 `推迟` 批次和最新检查已到 T+7 的批次。
2. T+N 中的 N 是选股日之后到数据日的 A 股交易日数量，不是自然日差。用沪深300的实际交易日期序列核对；无法取得交易日序列时，该批次记 `未跑（无法验证 T+N）`。
3. 从批次明细提取完整代码、排名和基准价；查询数据日收盘价、沪深300选股日收盘和数据日收盘。代码或基准缺失时不补编。
4. 逐只收益率 = `(数据日收盘价 / 基准价 - 1) × 100%`；沪深300同期收益同公式。绝对胜率统计收益率大于 0 的数量；跑赢沪深300统计个股收益率大于基准收益的数量。
5. 数量大于 10 的批次写全池、Top5、Top10；数量不大于 10 的批次按原表结构写逐只收益。若个别标的缺价，可按现有台账惯例写透明的部分样本结果，例如 `批均收益（22/30）`，所有胜率分母改成实际可用数量并列出缺失代码；不得把部分样本伪装成全池。基准价或沪深300同期数据缺失则跳过该批次。
6. 同一检查日只允许一行；已有同日行时更新原行，不重复追加。随后同步更新“批次汇总”的最新检查和指标。
7. 不新增选股批次，不改历史基准价，不更新 `选股策略胜率仪表盘.html`。

### 4. 生成盘后复盘骨架

创建或更新 `02-每日复盘/每日复盘总结/YYYY-MM-DD 盘后复盘.md`。把自动内容包在 `<!-- stock-daily:auto:start -->` 与 `<!-- stock-daily:auto:end -->` 之间，结构固定为：

- 数据来源、数据日、自动步骤状态。
- 账户快照：总市值、现金来源状态、总资产、仓位、卫星仓占比。
- 绩效状态：净值、累计 TWR、基准口径、超额收益、最大回撤和月内回撤。
- 持仓纪律对照：标的、收盘价、止损/上限、触发状态、证据。
- 今日交易：只摘录已存在且可追溯的当日交易记录；没有就写“未提供/未记录，不推断”。
- 选股台账 T+N：列出已更新批次和未跑原因。
- `## 今日盘面分析（留空）`，正文写“盘面分析不代写；需要深度复盘时使用 stock-buddy。”
- 次日待复核项：只从已触发纪律、到期复评和数据缺口生成。
- 末尾写非投顾声明、数据来源和数据日。

若文件已存在且有上述标记，只替换标记内数据；没有标记时保留原文并追加一个自动块。保留用户手写的盘面分析和复盘内容，不得整篇覆盖。

### 5. 生成次日清单并刷新首页

1. 用可验证的 A 股交易日历或交易所官方日历确定下一交易日。不得仅按“工作日”猜日期；无法验证时记 `未跑（无法验证下一交易日）`，不建错日期文件。
2. 创建或更新 `08-下个交易日/YYYY-MM-DD 开盘前行动清单.md`，把自动项包在 `<!-- stock-daily:auto:start -->` 与 `<!-- stock-daily:auto:end -->` 之间，采用一屏优先级表：优先级、标的/事项、纪律线、待核对动作、不做什么。
3. 内容只来自已触发红线、T+1 纪律、计划书到期复评、持仓缺口和券商核对项。用“复核/确认/关注”措辞，不替用户下买卖指令，不虚构次日价格。
4. 若同名文件已存在，只替换标记内自动项；没有标记时保留原文并追加自动块，查重后合并。
5. 更新 `投资笔记.md` 的“最新盘后复盘”和“下个交易日行动清单”链接；只改这两条静态入口。

### 6. git 快照（后）与回告

只暂存本轮白名单文件并提交：

```bash
git add -- '03-持仓跟踪/持仓.md' \
  '02-每日复盘/账户净值与绩效.md' \
  '09-选股池跟踪/选股策略胜率台账.md' \
  '02-每日复盘/每日复盘总结' \
  '08-下个交易日' \
  '投资笔记.md'
git commit -m "[ai:claude] 盘后例行 YYYY-MM-DD"
git rev-parse --short HEAD
```

若没有任何写入，不创建后快照空提交；报告“无变更”并保留前快照 hash。若有写入但提交失败，明确报告 git 阻塞，不能声称例行已完成。

最后在聊天中给出：数据日、六步完成/未跑状态、红线触发摘要、变更文件、前后 commit hash、所有缺口。结尾固定写：`研究分析，非持牌投顾建议，风险自担。数据来源：同花顺问财及投资笔记已验证记录，数据日 YYYY-MM-DD。`

## 熔断与幂等

- API 额度耗尽、认证失败、网络错误、空数据、日期不一致都视为数据源不可用；对应步骤写 `未跑（原因）`，绝不改用猜测值。
- 同一数据日重复触发时，先查重持仓变更记录、台账检查行、复盘文件、次日清单和首页链接；更新而不重复追加。
- 任何写入路径超出白名单立即停止并向用户说明需要额外授权。
- 运行结束后用 `git diff HEAD^ --name-only` 核对实际变更；发现 04/05/06/07 或 HTML 仪表盘被改动即判定失败并报告，不自行删除用户文件。
